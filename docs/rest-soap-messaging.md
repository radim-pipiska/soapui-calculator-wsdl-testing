# REST, SOAP a messaging očima testera

REST chování je z testování Vacation API, SOAP chování pozorováno na veřejném Calculatoru, messaging je z cvičení bez reálného brokeru.

| | REST | SOAP | Messaging |
| :--- | :--- | :--- | :--- |
| **Kontrakt (kde je popsaný, jak se jmenuje) /AI** | OpenAPI (Swagger) | WSDL + XSD | AsyncAPI |
| **Formát zprávy /AI** | Obvykle JSON (příp. XML) | XML | Dle kontraktu (obvykle JSON, Avro, Protobuf) |
| **Jak se pozná úspěch a jak chyba /AI** | **Úspěch:** HTTP 2xx (200, 201, 204) + validní payload.<br>**Chyba:** HTTP 4xx / 5xx nebo neplatná struktura dat. | **Úspěch:** HTTP 200 OK + validní XML bez `<Fault>`, odpovídající byznys logice.<br>**Chyba:** HTTP 500 + element `<soap:Fault>` (`faultcode` soap:Client / soap:Server). *Jde o SOAP 1.1 a o pozorování na Calculatoru.* | **Úspěch:** výrobce dostane od brokera potvrzení přijetí, konzument po zpracování pošle brokeru ACK a změní se stav. [OVĚŘIT]<br>**Chyba:** NACK, odmítnutí zprávy nebo její pád do DLQ (Dead Letter Queue). |
| **Co test kromě statusu musí ověřit** | Strukturu JSONu (schéma), konkrétní klíče, datové typy, hodnoty polí a uložení dat v DB. | Strukturu XML proti XSD, konkrétní hodnoty v elementech pomocí XPath Match. *Moje vlastní nálezy ale ukazují, že Schema Compliance a SOAP Response zůstaly zelené i na Faultu a u špatného namespace. XSD je tedy nutná podmínka, ne důkaz úspěchu. Rozhoduje aserce na hodnotu (XPath) spolu s „není Fault“.* | **Pro aserci:** Změnu stavu v databázi nebo odeslání navazující zprávy.<br>**Pro vyšetřování:** Aplikační logy. |
| **Jedna past, kterou jsem pozoroval** | Nedefinovaná proměnná `{{PersonId}}` (definovaná byla `personId`, Postman rozlišuje velikost písmen) se odeslala jako doslovný text. API takové jméno přijme a výsledek DDT běhu se při stejném testu měnil (160/160, 159/1, 143/17), pravděpodobně podle stavu API. Testy proto zezelenaly falešně. [Případová studie](postman-silent-failure-unresolved-variable.md) | Prázdný `intB` (u Divide, SOAP 1.1): aserce Valid HTTP Status Codes (500) a SOAP Fault zůstaly zelené i u chyby klienta, rozlišil až `faultcode` (`soap:Client`). Viz `notes.md`, řádek AL. | Z cvičení (příklad od AI): **pevná pauza**, číslo 5 sekund nebylo ze specifikace, limit musí dodat analytik. |
