# REST, SOAP a messaging očima testera

REST chování je z testování Vacation API, SOAP chování pozorováno na veřejném Calculatoru, messaging je z cvičení bez reálného brokeru.

| | REST | SOAP | Messaging |
| :--- | :--- | :--- | :--- |
| **Kontrakt (kde je popsaný, jak se jmenuje)** | OpenAPI (Swagger) | WSDL + XSD | AsyncAPI |
| **Formát zprávy** | Obvykle JSON (příp. XML) | XML | Dle kontraktu (obvykle JSON, Avro, Protobuf) |
| **Jak se pozná úspěch a jak chyba** | **Úspěch:** HTTP 2xx (200, 201, 204) + validní payload.<br>**Chyba:** HTTP 4xx / 5xx nebo neplatná struktura dat. [OVĚŘIT] | **Úspěch:** HTTP 200 OK + validní XML bez `<Fault>`, odpovídající byznys logice.<br>**Chyba:** HTTP 500 + element `<soap:Fault>` (`faultcode` soap:Client / soap:Server). *Jde o SOAP 1.1 a o pozorování na Calculatoru.* | **Úspěch:** ACK posílá konzument brokeru, výrobce dostává potvrzení přijetí od brokera. [OVĚŘIT]<br>**Chyba:** NACK, odmítnutí zprávy nebo její pád do DLQ (Dead Letter Queue). |
| **Co test kromě statusu musí ověřit** | Strukturu JSONu (schéma), konkrétní klíče, datové typy, hodnoty polí a uložení dat v DB. | Strukturu XML proti XSD, konkrétní hodnoty v elementech pomocí XPath Match. *Moje vlastní nálezy ale ukazují, že Schema Compliance a SOAP Response zůstaly zelené i na Faultu a u špatného namespace. XSD je tedy nutná podmínka, ne důkaz úspěchu. Rozhoduje aserce na hodnotu (XPath) spolu s „není Fault“.* | **Pro aserci:** Změnu stavu v databázi nebo odeslání navazující zprávy.<br>**Pro vyšetřování:** Aplikační logy. |
| **Jedna past, kterou jsem pozoroval** | **Past (REST buňka)**: název proměnné se v Postmanu rozlišuje podle velikosti písmen, nevyřešená se pošle doslova, výsledek DDT běhu závisel na stavu API (160/160, 159/1, 143/17 se stejným testem). **Otázka na analytika / kandidát na bug report**: API zapisuje záznamy pro nesmyslné *PersonId*. Specifikaci nemám, ale u tréninkového API s úmyslnými chybami je to přirozená položka do seznamu vad. **Pravidlo pro DDT**: každý běh má mít vlastní čistou testovací osobu, nebo úklid po sobě. | Prázdný **intB** (u Divide). **HTTP 500** i **SOAP Fault** prošly i u **chyby klienta** a rozlišil to až **faultcode**. Další pastí byla aserce na číslo 12+prázdný řádek v XPath Match. | Past „z cvičení“ AI: **pevná pauza**, číslo 5 sekund v příkladu nebylo ze specifikace, limit musí dodat analytik. |
